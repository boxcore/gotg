# Gotg

`gotg` 是一个轻量级、高性能的 Telegram Bot 运维及媒体辅助工具，旨在为运维开发提供便捷的 Bot 权限检测、批量媒体分发上传和本地媒体解析能力。

---

## ⚙️ 快速开始

### 1. 初始化项目与依赖
```bash
# 整理并同步依赖包
go mod tidy
```

### 2. 编译并生成二进制文件
```bash
# 编译为本地二进制可执行文件 gotg
go build -o gotg cmd/gotg/main.go
```

### 3. 配置运行环境
项目支持使用本地 `.env` 文件进行配置，您可以复制并修改模板：
```bash
cp .env.example .env
```
在 `.env` 中填写您的常驻配置：
```ini
TOKEN=12345678:AAHdU-Z25K2D7YDMvS997v818wA8tQFg8G0
CHAT_ID=@mychannel
API_URL=http://[IP_ADDRESS]
```

## 📋 命令行参数说明

- **-t, --task** `<task_type>` (**必填**)
  执行的任务类型。支持以下类型：
  - `check_auth` : 校验 Bot Token 状态与频道管理员权限
  - `up` : 批量分发上传媒体文件
  - `check_media` : 纯本地媒体（视频/图像）编码及规格深度解析

- **--token** `<tokens>` (**可选，可由 `.env` 提供**)
  Telegram Bot Token。支持传入多个 Token，以英文逗号 `,` 分隔，工具会自动对多个 Bot 进行任务轮询分发。

- **--chat_id** `<chat_id>` (**可选，可由 `.env` 提供**)
  接收媒体消息的目标频道用户名 (带 `@`) 或数字 ID (如 `-100xxx`)。

- **--api-url** `<url>` (**可选，可由 `.env` 提供**)
  自定义 Telegram Bot API Server 的 URL 地址。若为空，则默认向官方 API 发送请求。

- **-n, --group-size** `<size>` (**可选，默认值 `10`**)
  指定上传的媒体组文件数量大小（必须在 `1` 到 `10` 之间）。

- **--debug** `<mode>` (**可选**)
  调试模式选项。支持以下模式：
  - `list` : 测试打印目录下文件列表上传的顺序和分组，不执行任何实际上传。
  - `curl` : 打印模拟 curl 上传该媒体组的完整命令，不执行实际上传（可直接拷贝至终端测试）。


- **--sort** `<rule>` (**可选，默认值 `name_asc`**)
  指定上传文件列表的排序规则。支持以下规则：
  - `name_asc` : 按文件名自然升序（例如 `mp4_ (2).mp4` 将排在 `mp4_ (10).mp4` 之前）
  - `name_desc` : 按文件名自然降序
  - `size_asc` / `size_desc` : 按文件大小升序 / 降序
  - `mod_asc` / `mod_desc` : 按文件修改时间升序 / 降序
  - `created_asc` / `created_desc` : 按文件创建时间升序 / 降序（仅在 macOS 下有效，非 macOS 平台自动降级回退至修改时间）

- **-s, --sleep** `<seconds>` (**可选，默认值 `30`**)
  指定每个媒体组上传/模拟完成后，休眠等待的秒数，用于降低限流和风控概率。

- **-r, --r-rotation** (**可选**)
  启用多 Bot Token 轮询发送模式。每上传完一个媒体组，自动轮换使用下一个 Bot 发送，以稀释官方接口限流频率。如果仅配置了一个 Token 且启用了本标志，程序将打印风控警告并在 5 秒后超时自动安全退出。

- **--cache-dir** `<path>` (**可选，默认值 `~/.gotg/cache`**)
  指定本地元数据缓存与缩略图存放的目录。支持家目录 `~` 自动展开，不存在时程序将自动创建。

- **--cache-fresh** (**可选**)
  强制刷新媒体缓存。传入该 Flag 时，会强制重新通过 `ffprobe` / `goexif` 提取最新的文件元数据并重新生成 JPEG 缩略图和超限图片压缩版本。

- **--title** `<title>` (**可选**)
  指定媒体的标题。若未指定，默认将采用不带文件后缀的文件名。

- **--tag** `<tags>` (**可选**)
  指定媒体描述尾部需要追加的标签（例如 `"#网红 #美少女"`）。标签会以换行形式自动拼接在标题（Caption）后部，在 `curl` 模拟和实际上传中均能实现安全转义。

- **--force-up** (**可选**)
  强制重新上传已成功上传的文件。若未指定，系统在再次运行时会自动跳过本地缓存中上传状态为 `"success"` 的文件，实现极佳的断点续传体验。

- **--transcode** (**可选**)
  强制自动将不合规的视频文件（格式非 MP4/MOV，或视频编码非 H264/H265，或音频编码非 AAC）转码为 Telegram 播放规范的 H264 MP4 视频，而不需要控制台交互确认。若未加此标志，系统将触发 5 秒超时交互确认提示，未确认则自动跳过。

- **-v, --version** (**可选**)
  输出当前程序的软件版本号（当前版本：`v0.1.3`）。

- **-h, --help** (**可选**)
  打印帮助和使用说明。

> [!NOTE]
> **优先级规则**：如果同时提供了命令行 Flag 和 `.env` 配置，程序将**优先采用命令行 Flag 传递的参数**，仅在 Flag 未提供时才 fallback 去读取 `.env` 配置文件。

## 🚀 核心特性介绍

### 1. 自定义 API 与 2GB 超大媒体上传
*   **官方 API 模式**（未配置 `--api-url`）：受 Telegram 官方限制，单文件上传上限为 **50MB**。
*   **自定义 API 模式**（配置了 `--api-url`，如使用自建本地 Bot API 服务）：上传限制放宽至最大 **2GB** (2000MB)。
*   **本地智能拦截**：`gotg` 会在发送网络请求前先读取文件大小。一旦文件超过对应模式的上限（50MB 或 2GB），会自动拦截跳过并输出提示，避免因为网络传输过载或超时造成不必要的等待与流量消耗。

### 2. Token 安全脱敏
*   在执行任务（如 `check_auth` 或 `up`）输出 Bot 部署状态时，日志中打印的 Token 会被自动隐去核心密钥部分（如 `12345678:AAH***8G0`），从而在提供诊断所需辨识度的同时，杜绝录屏或日志截图中密钥泄露的安全风险。

### 3. 多 Bot 任务轮询分发
*   在 `--token` 参数中传入多个以逗号隔开的 Token 时，工具会轮询对每个 Bot 执行操作，提高上传分发效率并分散单一 API 限流风险。

### 4. 智能媒体预处理（图片压缩、缩略图与转码）
*   **图片超限检测与自适应压缩（`_tran.jpg`）**：
    为了确保媒体文件能够顺利上传并被 Telegram 正常接收，`gotg` 在上传前会自动分析图片文件大小与规格。如果满足以下任一条件，程序会自动通过 `ffmpeg` 将图片裁剪缩放并转码为符合 Telegram 规范的压缩版本进行上传：
    *   **文件大小限制**：单张图片文件大小大于 `10MB`。
    *   **尺寸限制**：图片的宽度与高度之和大于 `10,000` 像素。
    *   **宽高比限制**：图片的宽高比大于 `20.0` 或小于 `0.05`（即过长或过宽的图片）。
    
    *自适应处理逻辑*：
    1. **比例裁剪**：若宽高比大于 20.0，自动将宽度裁剪为 `高度 * 20`；若宽高比小于 0.05，自动将高度裁剪为 `宽度 * 20`（通过 `crop` 限制最大比例为 20:1，防止因图片比例极度失真被 Telegram 拒绝）。
    2. **等比缩放**：若裁剪后的宽高之和仍大于 `9,900` 像素，则会按比例等比缩小，确保缩放后的 `宽 + 高 <= 9,900`（通过 `scale` 缩放）。
    3. **质量压缩**：使用 `ffmpeg -q:v 5` 品质等级（在体积与画质间取得优秀平衡）导出为 JPEG 格式并缓存为 `<sha1>_tran.jpg`。
    
*   **缩略图自动生成（`_thumb.jpg`）**：
    自动为上传的视频（`video`）和图片（`image`）生成轻量级缩略图，以使 Telegram 客户端能够正常渲染媒体组预览图：
    *   **视频截图**：默认使用 `ffmpeg` 提取视频在 `00:00:00` 处（首帧）的图像。
    *   **等比缩放**：采用自适应缩放（`scale='if(gt(iw,ih),320,-1)':'if(gt(iw,ih),-1,320)'`）。横屏图片/视频宽度缩放为 `320px`；竖屏或方形缩放高度为 `320px`，另一边按比例自动缩放。
    *   **输出质量**：使用 `ffmpeg -q:v 5` 画质等级导出为 JPEG 格式并缓存为 `<sha1>_thumb.jpg`。

*   **视频合规性检测与自动转码**：
    *   **合规标准**：当视频后缀非 `.mp4`/`.mov`、或视频编码非 `H.264`/`H.265`/`HEVC`、或音频编码存在但非 `AAC` 时，由于无法在 Telegram 客户端中直接在线播放，会被判定为不合规。
    *   **转码机制**：未附加 `--transcode` 标志时，工具会交互式向用户确认是否转码（支持 5 秒超时自动跳过）。使用 `--transcode` 标志后，工具将全自动进行转码。
    *   **编码器优先选择**：自动探测并优先采用硬件加速编码器（优先级：`h264_videotoolbox` > `h264_nvenc` > `h264_amf` > `h264_qsv` > 软件编码 `libx264`），将其转码为标准的 H.264 MP4 视频。

## 💡 使用示例

#### 示例 1：检测 Bot 是否有频道的管理员权限
```bash
./gotg -t check_auth
```
*(如果没有配置 `.env` 文件，则必须在命令行传参)*：
```bash
./gotg -t check_auth --token="123456:AAH..." --chat_id="@mychannel"
```

#### 示例 2：使用自定义 API 批量上传文件夹下的所有文件
```bash
./gotg -t up --api-url="http://[IP_ADDRESS]" /path/to/media/directory
```

#### 示例 3：纯本地深度解析视频或图片的编码与格式
*(纯本地任务，无需网络及 Token)*：
```bash
./gotg -t=check_media /path/to/video.mp4
```

## 📜 版本历史

### v0.1.3
*   **多 Bot Token 轮询模式 (-r)**：在配置多个 Token 时，可启用 `-r` / `--r-rotation` 标志，使程序在每上传完一个媒体组后轮换至下一个 Token 发送，以稀释并对抗 Telegram 的频控与风控。如果仅配置单个 Token，将弹出警告并倒计时自动确认。
*   **上传起点下沉至二级目录**：多级目录扫描逻辑下沉，直接将二级目录名用作媒体组标题，各子目录层级则以 `二级目录名/子目录` 复合格式拼装。
*   **子目录层级上限限制**：自动将目录递归扫描深度限制在最多 3 层（三级目录下文件），避免因目录过深及极多文件导致的内存溢出。
*   **组包标题编号与消隐机制**：对单个目录分包上传的媒体，自动按顺序追加组号后缀 `(1)`、`(2)` 等。若用户在命令行或交互输入中提供了特定大标题，则首个发送的媒体组包隐藏编号；子目录的媒体组也进行相应标题拼装。
*   **WebDAV 大文件分段流式读取**：优化 WebDAV 的 IO 读取，不再将大文件一次性在内存中缓存，而是通过分段流式传输有效保障大文件转码及上传过程中的极低内存占用。

### v0.1.2
*   **媒体组上传功能完善**：将原本的单文件独立上传逻辑优化为支持最多 10 张媒体/组的 `SendMediaGroup` 合并打包上传，符合 Telegram 高级相册呈现习惯。
*   **视频合规性检测与自动转码**：新增视频规格检验，支持命令行参数 `--transcode` 静默强转或 5 秒超时交互确认，智能探测并优先调用本地硬件加速编码器。
*   **断点续传体验优化**：改进本地 JSON 缓存元数据的状态标记，在成功上传后彻底清理临时转码文件，防止因多次重复运行造成流量浪费。
*   **分组及调试工具**：新增 `-n` / `--group-size` 参数用以调控单媒体组的大小上限；新增 `--debug` 参数，支持 `list`（本地组列表）和 `curl`（curl 命令行模拟）两类无害调试选项。
*   **更自由的排序**：新增 `--sort` 规则，支持按名称、修改时间、创建时间（macOS 特有）等多维度自然升降序排列。

### v0.1.1
*   **自定义 API 服务器（2GB 突破）**：支持传入 `--api-url` 参数以选用本地自建 Telegram API 服务器，将单媒体文件上传大小限制由官方 API 的 50MB 极大突破至 2GB。
*   **Token 安全脱敏防护**：日志输出时对 Bot Token 的敏感密匙段（Secret）进行自动掩码脱敏（如显示为 `12345:AAH***8G0`），杜绝截屏或日志分享中发生泄漏。
*   **多 Bot Token 负载轮询**：支持以逗号分隔传入多个 Token，由程序自动依次检测 Bot 授权状态与频道管理员权限。
*   **核心命令行任务框架**：完成了 `check_auth`、`up`、`check_media` 三项核心业务流程的搭建。
