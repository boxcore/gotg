# Gotg

`gotg` 是一个轻量级、高性能的 Telegram Bot 运维及媒体辅助工具，旨在为运维开发提供便捷的 Bot 权限检测、批量媒体分发上传和本地媒体解析能力。

---

## ⚙️ 快速开始

### 📥 自动下载安装最新发布版 (推荐)

直接在终端运行以下一键命令，程序将自动识别您的操作系统 (Linux/macOS) 及架构，下载最新的 `gotg` 发布包并安装至系统的 `/usr/local/bin` 目录：

```bash
curl -s https://api.github.com/repos/boxcore/gotg/releases/latest \
| grep "browser_download_url.*$(uname -s | tr '[:upper:]' '[:lower:]')-$(uname -m | sed 's/x86_64/amd64/' | sed 's/aarch64/arm64/')" \
| cut -d : -f 2,3 | tr -d \" | xargs curl -L -o gotg.tar.gz \
&& tar -xzf gotg.tar.gz \
&& sudo mv gotg /usr/local/bin/ \
&& rm gotg.tar.gz README.md
```

*提示: 在执行上面命令时，若提示 `/usr/local/bin` 权限不足，会自动调用 `sudo` 提权。*

## 📋 命令行参数说明

- **-t, --task** `<task_type>` (**必填**)
  执行的任务类型。支持以下类型：
  - `check_auth` : 校验 Bot Token 状态与频道管理员权限
  - `up` : 批量分发上传媒体文件或单个媒体文件
  - `check_media` : 纯本地媒体（视频/图像）编码及规格深度解析

- **--token** `<tokens>` (**可选，可由 `.env` 提供**)
  Telegram Bot Token。支持传入多个 Token，以英文逗号 `,` 分隔，工具会自动对多个 Bot 进行任务轮询分发。

- **--chat_id** `<chat_id>` (**可选，可由 `.env` 提供**)
  接收媒体消息的目标频道用户名 (带 `@`) 或数字 ID (如 `-100xxx`)。

- **--api-url** `<url>` (**可选，可由 `.env` 提供**)
  自定义 Telegram Bot API Server 的 URL 地址。若为空，则默认向官方 API 发送请求。

- **-n, --group-size** `<size>` (**可选，默认值 `10`**)
  指定上传的媒体组文件数量大小（必须在 `1` 到 `10` 之间）。

- **--debug** `<mode>` (**可选**)
  调试模式选项。支持以下模式：
  - `list` : 测试打印目录下文件列表上传的顺序和分组，不执行任何实际上传。
  - `curl` : 打印模拟 curl 上传该媒体组的完整命令，不执行实际上传（可直接拷贝至终端测试）。


- **--sort** `<rule>` (**可选，默认值 `name_asc`**)
  指定上传文件列表的排序规则。支持以下规则：
  - `name_asc` : 按文件名自然升序（例如 `mp4_ (2).mp4` 将排在 `mp4_ (10).mp4` 之前）
  - `name_desc` : 按文件名自然降序
  - `size_asc` / `size_desc` : 按文件大小升序 / 降序
  - `mod_asc` / `mod_desc` : 按文件修改时间升序 / 降序
  - `created_asc` / `created_desc` : 按文件创建时间升序 / 降序（仅在 macOS 下有效，非 macOS 平台自动降级回退至修改时间）

- **-s, --sleep** `<seconds>` (**可选，默认值 `30`**)
  指定每个媒体组上传/模拟完成后，休眠等待的秒数，用于降低限流和风控概率。

- **-r, --r-rotation** (**可选**)
  启用多 Bot Token 轮询发送模式。每上传完一个媒体组，自动轮换使用下一个 Bot 发送，以稀释官方接口限流频率。如果仅配置了一个 Token 且启用了本标志，程序将打印风控警告并在 5 秒后超时自动安全退出。

- **--thumb-min-size** `<megabytes>` (**可选，默认值 `2`**)
  指定图片生成缩略图的最小体积阈值限制（单位为 MB）。当图片小于等于该阈值时将不生成本地缩略图，以减小磁盘 IO。但若图片规格超过 Telegram 官方像素或比例超限，将自动触发转码压缩不受该阈值限制。

- **--cache-dir** `<path>` (**可选，默认值 `~/.gotg/cache`**)
  指定本地元数据缓存与缩略图存放的目录。支持家目录 `~` 自动展开，不存在时程序将自动创建。

- **--cache-fresh** (**可选**)
  强制刷新媒体缓存。传入该 Flag 时，会强制重新通过 `ffprobe` / `goexif` 提取最新的文件元数据并重新生成 JPEG 缩略图和超限图片压缩版本。

- **--title** `<title>` (**可选**)
  指定媒体的标题。若显式提供此参数（包括 `--title=""` 指定为空），程序将强制跳过上传前关于标题使用的交互提问。若未提供此参数，单文件或单目录任务在非轮询模式下会自动询问是否使用文件名/目录名作为标题。

- **--tag** `<tags>` (**可选**)
  指定媒体描述尾部需要追加的标签（例如 `"#网红 #美少女"`）。标签会以换行形式自动拼接在标题（Caption）后部，在 `curl` 模拟和实际上传中均能实现安全转义。

- **--force-up** (**可选**)
  强制重新上传已成功上传的文件。若未指定，系统在再次运行时会自动跳过本地缓存中上传状态为 `"success"` 的文件，实现极佳的断点续传体验。

- **--transcode** (**可选**)
  强制自动将不合规的视频文件（格式非 MP4/MOV，视频编码非 H264/H265/HEVC，或音频编码非 AAC 且未被豁免）转码为 Telegram 播放规范的 H264 MP4 视频，而不需要控制台交互确认。若未加此标志，系统将触发 5 秒超时交互确认提示，未确认则自动跳过。（注：对于 `.mov` 容器，若音频编码为常见的苹果原生高质量编码如 `pcm_s16le`/`pcm_s24le`/`alac`/`lpcm`，系统会自动豁免，无需转码）。

- **--notify-id** `<uid/chat_id>` (**可选**)
  任务完成后发送统计报告的目标 Telegram 用户 UID（如 `413423580`）或群组/频道的 Chat ID。若指定，则在实际上传任务全部结束后，自动通过第一个 Bot 向该 ID 发送包含执行服务器、目标路径、完成时间（东八区）、任务耗时、媒体组成功/失败状态、失败文件资源明细以及总上传数量的 HTML 格式精美报告。可通过命令行 Flag 或环境变量 `NOTIFY_ID` 配置。

- **-v, --version** (**可选**)
  输出当前程序的软件版本号（当前版本：`v0.1.6`）。

- **-h, --help** (**可选**)
  打印帮助和使用说明。

> [!NOTE]
> **优先级规则**：如果同时提供了命令行 Flag 和 `.env` 配置，程序将**优先采用命令行 Flag 传递的参数**，仅在 Flag 未提供时才 fallback 去读取 `.env` 配置文件。

## 🚀 核心特性介绍

### 1. 自定义 API 与 2GB 超大媒体上传
*   **官方 API 模式**（未配置 `--api-url`）：受 Telegram 官方限制，单文件上传上限为 **50MB**。
*   **自定义 API 模式**（配置了 `--api-url`，如使用自建本地 Bot API 服务）：上传限制放宽至最大 **2GB** (2000MB)。
*   **本地智能拦截**：`gotg` 会在发送网络请求前先读取文件大小。一旦文件超过对应模式的上限（50MB 或 2GB），会自动拦截跳过并输出提示，避免因为网络传输过载或超时造成不必要的等待与流量消耗。

### 2. Token 安全脱敏
*   在执行任务（如 `check_auth` 或 `up`）输出 Bot 部署状态时，日志中打印的 Token 会被自动隐去核心密钥部分（如 `12345678:AAH***8G0`），从而在提供诊断所需辨识度的同时，杜绝录屏或日志截图中密钥泄露的安全风险。

### 3. 多 Bot 任务轮询分发
*   在 `--token` 参数中传入多个以逗号隔开的 Token 时，工具会轮询对每个 Bot 执行操作，提高上传分发效率并分散单一 API 限流风险。

### 4. 智能媒体预处理（图片压缩、缩略图与转码）
*   **图片超限检测与自适应压缩（`_tran.jpg`）**：
    为了确保媒体文件能够顺利上传并被 Telegram 正常接收，`gotg` 在上传前会自动分析图片文件大小与规格。如果满足以下任一条件，程序会自动通过 `ffmpeg` 将图片裁剪缩放并转码为符合 Telegram 规范的压缩版本进行上传：
    *   **文件大小限制**：单张图片文件大小大于 `10MB`。
    *   **尺寸限制**：图片的宽度与高度之和大于 `10,000` 像素。
    *   **宽高比限制**：图片的宽高比大于 `20.0` 或小于 `0.05`（即过长或过宽的图片）。
    
    *自适应处理逻辑*：
    1. **比例裁剪**：若宽高比大于 20.0，自动将宽度裁剪为 `高度 * 20`；若宽高比小于 0.05，自动将高度裁剪为 `宽度 * 20`（通过 `crop` 限制最大比例为 20:1，防止因图片比例极度失真被 Telegram 拒绝）。
    2. **等比缩放**：若裁剪后的宽高之和仍大于 `9,900` 像素，则会按比例等比缩小，确保缩放后的 `宽 + 高 <= 9,900`（通过 `scale` 缩放）。
    3. **质量压缩**：使用 `ffmpeg -q:v 5` 品质等级（在体积与画质间取得优秀平衡）导出为 JPEG 格式并缓存为 `<sha1>_tran.jpg`。
    
*   **缩略图自动生成（`_thumb.jpg`）**：
    自动为上传的视频（`video`）和图片（`image`）生成轻量级缩略图，以使 Telegram 客户端能够正常渲染媒体组预览图：
    *   **图片缩略图阈值**：仅在图片文件大小超过指定阈值时（可通过 `--thumb-min-size` 配置，默认 `2MB`）才生成缩略图，普通小图自动跳过缩略图生成以减小不必要的本地 IO。
    *   **视频截图与自适应黑屏检测**：默认使用 `ffmpeg` 提取视频在 `00:00:00` 处（首帧）的图像，以确保在线视频在客户端加载播放时的连贯平滑性。若自动检测到截出的首帧图像为纯黑屏（利用内置亮度分析算法，当平均亮度低于 `10/255` 时判定为黑屏且视频总时长大于 1.0 秒），则会自动回退并在视频的第 1 秒（`00:00:01`）重新截图进行覆盖，有效规避过渡淡入造成的纯黑预览图问题。
    *   **等比缩放**：采用自适应缩放（`scale='if(gt(iw,ih),320,-1)':'if(gt(iw,ih),-1,320)'`）。横屏图片/视频宽度缩放为 `320px`；竖屏或方形缩放高度为 `320px`，另一边按比例自动缩放。
    *   **输出质量**：使用 `ffmpeg -q:v 5` 画质等级导出为 JPEG 格式并缓存为 `<sha1>_thumb.jpg`。

*   **视频合规性检测与自适应免转码机制**：
    *   **智能免转码判定**：并非所有 `.mov` / `.mp4` 视频都需要转码。对于 `.mov` 和 `.mp4` 封装的视频，只要其内部视频流编码为标准的 `H.264` 或 `H.265 (HEVC)`，且音频流编码为 `AAC`（或无声）时直接放行。另外，为了照顾苹果生态下的高保真原生录制视频，对于 `.mov` 封装，若其音频流为常见的苹果原生高质量编码（如 `pcm_s16le`/`pcm_s24le`/`alac`/`lpcm`），系统亦会判定为**完全合规**，免予强制转码原样上传，以最大化保留原始画质并避免 CPU 浪费。
    *   **强制转码标准**：只有当视频后缀非 `.mp4`/`.mov`、或视频编码非 `H.264`/`H.265`/`HEVC`（例如旧版格式、ProRes 专业无损编码）、或音频编码存在但非 `AAC`（且在 `.mov` 下不属于上述苹果原生高质量豁免音频编码如 PCM/ALAC 等）时，为了确保在 Telegram 各客户端平台上都能流畅在线预览，才会被判定为不合规，触发转码提示。
    *   **转码机制**：未附加 `--transcode` 标志时，工具会交互式向用户确认是否转码（支持 5 秒超时自动跳过）。使用 `--transcode` 标志后，工具将全自动进行转码。
    *   **编码器优先选择**：自动探测并优先采用硬件加速编码器（优先级：`h264_videotoolbox` > `h264_nvenc` > `h264_amf` > `h264_qsv` > 软件编码 `libx264`），将其转码为标准的 H.264 MP4 视频。

*   **多模式标题命名机制**：
    为了方便用户灵活对上传的媒体组附加标题（Caption），`gotg` 提供了四种标题命名规则。在命令行未传递 `--title` 参数且处于交互模式下，程序会在启动时显示数字菜单供用户选择（支持 5 秒超时无输入默认选择 `0` 跳过）：
    *   **0. 不设置标题 (默认)**：上传的媒体组将不包含任何前缀标题。如果一个目录下文件超过单组大小导致分包，仅会附带分包编号（如 `（1）`，`（2）`）。
    *   **1. 使用二级目录名称作为标题** (`child-dir-name`)：
        *   *单文件*：自动回退为使用文件名。
        *   *根目录下直属文件*：以根目录文件夹名作为标题。
        *   *二级子目录*：以各二级子目录名作为标题（子目录下的三级子目录则拼接为 `二级目录名/三级子目录` 格式）。
    *   **2. 使用文件名作为标题** (`file-name`)：
        *   *单文件*：直接使用该文件名（不含后缀）。
        *   *目录*：程序分包时，会自适应地提取每个媒体分包组中**第一个文件的文件名**（不含后缀）作为该组的标题，实现基于文件名的智能流式命名。
    *   **3. 自定义输入标题** (`input-name`)：
        *   在终端输入 `3` 后会进一步要求输入特定的标题文字。若您在命令行指定了 `--title="custom"`（即使指定为空 `--title=""`），程序将**强行跳过选择菜单**并直接应用此设定。

## 💡 使用示例

#### 示例 1：检测 Bot 是否有频道的管理员权限
```bash
./gotg -t check_auth
```
*(如果没有配置 `.env` 文件，则必须在命令行传参)*：
```bash
./gotg -t check_auth --token="123456:AAH..." --chat_id="@mychannel"
```

#### 示例 2：使用自定义 API 批量上传文件夹下的所有文件或单个文件
*   **批量文件夹上传**：
    ```bash
    ./gotg -t up --api-url="http://[IP_ADDRESS]" /path/to/media/directory
    ```
*   **单个文件上传**（未开启轮询 `-r` 模式且未指定 `--title` 时，会交互询问是否以文件名作标题）：
    ```bash
    ./gotg -t up --api-url="http://[IP_ADDRESS]" /path/to/media/video.mp4
    ```

#### 示例 3：纯本地深度解析视频或图片的编码与格式
*(纯本地任务，无需网络及 Token)*：
```bash
./gotg -t=check_media /path/to/video.mp4
```

## 📜 版本历史

### v0.1.6
*   **苹果原生 `.mov` 常见音频豁免**：针对 `.mov` 容器下的苹果原生常见高质量音频编码（`pcm_s16le`、`pcm_s24le`、`alac`、`lpcm`）免予强制转码直传，保护原始无损音质并避免冗长转码时间。
*   **标题命名规则交互菜单优化**：整合了之前分散在各分支处的提问，支持统一的数字选择菜单（二级目录名、文件名、自定义输入、不设标题），提供 5 秒超时默认选 0 选项。命令行传入 `--title`（含 `--title=""`）时强制跳过全部交互菜单。选择文件名模式时自适应提取每个分包首文件名去除后缀作为分包标题。
*   **混合目录直属文件漏扫修复**：在二级子目录并存的混合架构中，自动检测根目录本身是否直接包含媒体文件，并作为首个独立任务添加，确保无漏扫，同时配合非递归机制隔离子目录任务防止重复。
*   **任务完成通知与统计报告**：支持通过 `--notify-id` 参数或 `.env`/环境变量 `NOTIFY_ID` 指定接收人的 Telegram UID（如 `123456789`）或频道/群组的 Chat ID。在任务结束时，程序将自动通过第一个 Bot 以 HTML 格式发送包含执行服务器、目标路径、完成时间（东八区/CST）、总耗时、媒体组成功/失败数、失败文件明细等维度的精美总结报告。

### v0.1.5
*   **视频首帧黑屏截图自适应覆盖**：实现了对视频缩略图的智能亮度探测。默认依旧在视频首帧（`00:00:00`）处截图以保障在线播放的无缝平滑；若内置亮度算法检测到首帧为纯黑过渡，且视频时长支持，系统会自动退至第 1 秒（`00:00:01`）重新截图覆盖，防止预览图出现纯黑。
*   **旋转视频变形压缩全面修复**：全面支持对携带 Display Matrix 旋转角度（90度/270度）的常规视频及转码后探测流自动翻转宽高数据进行上报，彻底解决在 Telegram 客户端中的画面比例拉伸变形问题。
*   **无二级子目录直接单目录/单文件上传支持**：重构了扫描及任务规划逻辑。当目标路径下没有任何二级子目录时，系统会自动将该目录本身作为任务进行解析和上传。更进一步地，支持直接在参数中**传入单个媒体文件路径**进行极速直传，且在非 `-r` 轮询模式下会自动询问是否使用不带后缀的文件名作为视频/图片标题。
*   **本地媒体检测 (`check_media`) 升级**：同步支持了视频旋转度数与实际播放分辨率的深度检测与直观格式输出。

### v0.1.4
*   **并行预取机制**：重构媒体组分包的预处理与上传流程。在主线程上传当前媒体组以及休眠期间，后台使用流水线通道（goroutine channel）并行预处理下一波的媒体文件（如 ffprobe 信息获取、ffmpeg 缩略图生成、视频转码等），最大化消除了本地磁盘及计算瓶颈带来的等待耗时。
*   **图片缩略图阈值参数 (`--thumb-min-size`)**：提供命令行 Flag 与环境变量 `THUMB_MIN_SIZE` double/双重设置图片生成本地缩略图的最低体积限制（默认 `2` MB）。对于在此阈值以下的常规普通小图，将不再执行耗费 IO 性能的 `ffmpeg` 缩略图生成。同时该参数绝不影响 Telegram 官方对于像素、比例和文件超大限额的智能强制重置转码规则。

### v0.1.3
*   **多 Bot Token 轮询模式 (-r)**：在配置多个 Token 时，可启用 `-r` / `--r-rotation` 标志，使程序在每上传完一个媒体组后轮换至下一个 Token 发送，以稀释并对抗 Telegram 的频控与风控。如果仅配置单个 Token，将弹出警告并倒计时自动确认。
*   **上传起点下沉至二级目录**：多级目录扫描逻辑下沉，直接将二级目录名用作媒体组标题，各子目录层级则以 `二级目录名/子目录` 复合格式拼装。
*   **子目录层级上限限制**：自动将目录递归扫描深度限制在最多 3 层（三级目录下文件），避免因目录过深及极多文件导致的内存溢出。
*   **组包标题编号与消隐机制**：对单个目录分包上传的媒体，自动按顺序追加组号后缀 `(1)`、`(2)` 等。若用户在命令行或交互输入中提供了特定大标题，则首个发送的媒体组包隐藏编号；子目录的媒体组也进行相应标题拼装。
*   **WebDAV 大文件分段流式读取**：优化 WebDAV 的 IO 读取，不再将大文件一次性在内存中缓存，而是通过分段流式传输有效保障大文件转码及上传过程中的极低内存占用。

### v0.1.2
*   **媒体组上传功能完善**：将原本的单文件独立上传逻辑优化为支持最多 10 张媒体/组的 `SendMediaGroup` 合并打包上传，符合 Telegram 高级相册呈现习惯。
*   **视频合规性检测与自动转码**：新增视频规格检验，支持命令行参数 `--transcode` 静默强转或 5 秒超时交互确认，智能探测并优先调用本地硬件加速编码器。
*   **断点续传体验优化**：改进本地 JSON 缓存元数据的状态标记，在成功上传后彻底清理临时转码文件，防止因多次重复运行造成流量浪费。
*   **分组及调试工具**：新增 `-n` / `--group-size` 参数用以调控单媒体组的大小上限；新增 `--debug` 参数，支持 `list`（本地组列表）和 `curl`（curl 命令行模拟）两类无害调试选项。
*   **更自由的排序**：新增 `--sort` 规则，支持按名称、修改时间、创建时间（macOS 特有）等多维度自然升降序排列。

### v0.1.1
*   **自定义 API 服务器（2GB 突破）**：支持传入 `--api-url` 参数以选用本地自建 Telegram API 服务器，将单媒体文件上传大小限制由官方 API 的 50MB 极大突破至 2GB。
*   **Token 安全脱敏防护**：日志输出时对 Bot Token 的敏感密匙段（Secret）进行自动掩码脱敏（如显示为 `12345:AAH***8G0`），杜绝截屏或日志分享中发生泄漏。
*   **多 Bot Token 负载轮询**：支持以逗号分隔传入多个 Token，由程序自动依次检测 Bot 授权状态与频道管理员权限。
*   **核心命令行任务框架**：完成了 `check_auth`、`up`、`check_media` 三项核心业务流程的搭建。
